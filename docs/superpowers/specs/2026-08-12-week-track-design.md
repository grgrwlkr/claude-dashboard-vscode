# Недельная дорожка: одна шкала вместо двух

**Статус:** согласовано 2026-08-12. Вариант B2 из трёх показанных.

## Проблема

`paceTrack` в [dashboard.js](../../../dashboard.js) рисует на одном рельсе шесть элементов,
которые лежат на **двух разных шкалах**:

| Элемент | Шкала | Величина |
|---|---|---|
| заливка `.track-fill` | деньги | `weekly.pct` |
| кромка `.track-edge` | деньги | `weekly.pct` |
| засечка `.track-now` | время | `(сейчас − старт) / 7d` |
| флажок `.track-dry` | время | `(dryAt − старт) / 7d` |
| левый край | время | окно открылось |
| правый край | время | сброс |

Точка «92 % ширины» означает одновременно «потрачено 92 % лимита» (для заливки) и
«прошло 92 % недели» (для флажка). Эти величины несравнимы, но нарисованы на одной
линейке, поэтому взаимное положение заливки и флажка не значит ничего.

Владелец задал ровно тот вопрос, который эта геометрия порождает: «если заливка перешла
`dry`, я уже всё потратил?». Ответ — нет, и никакого события в этот момент не происходит.
Замер: из 10 201 пары `(pct, plan)` флажок оказывается левее кромки заливки в большинстве
рабочих режимов (90/50, 98/88, 71/42 — все левее), то есть это норма, а не сигнал.

Вторая половина проблемы — подавление подписей. `crowded` (расстояние меньше 11 %) гасит
подпись `now`, поэтому в самом тревожном состоянии — когда прогноз подошёл вплотную —
с экрана пропадает имя засечки.

## Решение

**Рельс меряет только время.** Прошлое, «сейчас», прогноз и сброс — всё на одной оси.
Деньги уходят в заголовок словами и не претендуют на геометрию.

```
THIS WEEK                                    92% spent · 8% ahead of plan
┌──────────────── прошло ────────────────┬── на лимите ──┬─ без лимита ─┐
│░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░│▓▓▓▓▓▓▓▓ 2d3h ▓│▓▓▓▓ 1d8h ▓▓▓│
└────────────────────────────────────────┴───────────────┴─────────────┘
window opened                          NOW              DRY   resets in 3d12h
```

Шесть элементов, все на шкале времени:

| № | Элемент | Что показывает |
|---|---|---|
| 1 | серая заливка | какая часть недели прошла |
| 2 | её правый край | «сейчас» — отдельной засечки нет, край её заменяет |
| 3 | зелёная плашка | сколько ещё продержишься на лимите, число внутри |
| 4 | красная черта `dry` | момент, когда лимит кончится |
| 5 | красная плашка | сколько недели проживёшь без лимита, число внутри |
| 6 | правый край | сброс |

### Почему подписи перестают сталкиваться

Имя `now` уезжает на этаж под рельсом, `dry` — на этаж над ним. Наложение невозможно
при любой близости, поэтому `crowded` удаляется целиком: **имя засечки не гасится никогда**.
Переносится только число длительности — из плашки в нижнюю строку, когда плашка уже́ его.

### Почему `dry` не может оказаться левее `now`

`dryAt = now + elapsed·(100−pct)/pct`, второе слагаемое неотрицательно. Проверено перебором
9 801 комбинации `(pct, доля прошедшего времени)`: нарушений ноль. `pace()` пересчитывается
на каждом тике от текущего момента ([extension.js](../../../extension.js) `d.pace = u.pace(d.weekly, d.now)`),
поэтому устаревший прогноз в прошлом остаться не может.

При исчерпании лимита `pct = 100` даёт `dryAt = now`: плашки «на лимите» нет, флажок не
рисуется, весь остаток недели — сплошная красная плашка с числом внутри.

### Числа берутся из остатка времени, а не из позиций

```
aliveS = min(resetIn, (dry − now)·7d)
tailS  = resetIn − aliveS
```

Так `alive + tail` всегда равно `resets in …` рядом. Расчёт напрямую из позиций даёт
расхождение в десятки минут — поймано на мокапе (`16h48m` против `resets in 16h0m`).

### Состояния

| Состояние | Условие | Отрисовка |
|---|---|---|
| обычное | `dry` внутри окна | зелёная + красная плашки |
| не кончится | `dry > 1` | одна зелёная до правого края, внизу `lasts to the reset` |
| прогноза нет | `dry === null` (первые 30 мин или `pct < 2`) | только заливка, внизу `too early to forecast` |
| лимит исчерпан | `aliveS < 60 с` | одна красная от «сейчас» до края, внутри `Nd Nh without quota` |

### Цвет

Зелёная плашка — `--vscode-charts-green`, красная — `--vscode-charts-red`, обе через
`color-mix`. Тревога выражена **длиной красного**, а не оттенком: нет хвоста — нечего
бояться. Порог `meterTone` (50/80 % от `pct`) на этой дорожке не применяется — он про
деньги, а рельс про время.

## Отдельно: шестиклеточный бар в статусбаре

Не косметика — он врёт. `f = ceil(fact·6/100)` против `p = round(plan·6/100)`: при близких
значениях `f` перескакивает `p` и рисуется ложный `▓` «перерасход». Замер: 216 пар из
10 201 показывают перерасход при `fact ≤ plan`. Худший случай — `fact=1, plan=8` рисует
`▓░░░░░`, а `84/90` (отстаём) и `92/84` (обгоняем) рисуются **одинаково**.

В `~/.claude/statusline.sh` этот баг уже починен, и комментарий над `bar_paced` описывает
его теми же словами: «краснело, идя по графику (ceil 6.1 → 7 перепрыгнул round 6.3 → 6)».
Два правила оттуда переносятся в `bar()`:

1. `▓` рисуется только при `fact > plan`;
2. при `fact > plan && p >= f` ставится `p = f − 1`, чтобы реальному перерасходу
   досталась хотя бы одна ячейка.

Ширина остаётся 6 (в shell — 10); это настройка, а не контракт.

Глифы меняются на монотонную шкалу плотности: `█` потрачено · `▓` сверх плана ·
`▒` план впереди · `░` пусто. Уходит `·`, выпадавшая из шкалы.

Двумя коммитами: багфикс отдельно от смены глифов, чтобы фикс можно было откатить сам по себе.

## Проверка

`tools/preview.js` меряет только выход за границы контейнера — наложение двух подписей
он поймать не может. Поэтому проба в `track-probe.js` сравнивает прямоугольники подписей
между собой и **сначала прогоняется против заведомо плохого входа**: `pct 98 / plan 88`
с выключенным разведением по этажам обязана дать пересечение. Иначе это не проверка.

Скриншоты обеих тем — обязательны (`Chromium` через headless, плюс WebKit, если доступен).

## Что отклонено

- **B1**, одна зона с тоном по запасу: жизнь без лимита остаётся неподписанной пустотой.
- **C**, рельс только из остатка до сброса, без прошлого: владелец отверг по виду.
- **Оставить как есть, поправив подписи**: не убирает две шкалы, вопрос «заливка перешла
  флажок» остаётся задаваемым.
